# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

EM residency shift scheduler (UH Emergency Medicine). Builds/validates resident schedules across areas (POD, PED, FLEX, MT, TRAUMA), auto-generates from coverage rules, exports CSV/PDF/QGenda, JSON backup/restore in Settings.

**Full-detail version of this doc (war stories, measurements, rationale): `docs/CLAUDE-full.md`. This file is the compact operational version — every rule here is load-bearing; consult the full doc before relaxing one.**

## Commands
```bash
npm run dev
npm run build     # → dist/
npm run preview
npm test          # vitest, ~930 tests. 2 skips = SOLVER_PARITY-gated files (need Python)
npx vitest run src/lib/qgenda.test.js        # single file
```
- No ESLint config exists. UI/tabs in `ResidentScheduler.jsx` have no tests — verify via `npm run dev` + generate/export a sample schedule. Generator core IS tested via named exports (`generateSchedule`, `generateScheduleBest`, `validateAll`, `getEligibleShifts`, `buildQualityInput`, `useMonthPager`).
- Quality baselines: `UPDATE_QUALITY_BASELINE=1 npm test` regenerates `qualityBaseline.<variant>.json` (refuses worse numbers unless `FORCE_QUALITY_BASELINE=1` also set). Baselines averaged over 5 seeds with tolerance margins; split one-file-per-variant (`generator.baseline.<variant>.test.js`) so vitest parallelizes across files — **don't recombine**, and each variant owns its own JSON (shared file would clobber under parallel update). `vitest.config.js` sets 120s test/hook timeouts (work happens in `beforeAll`).
- Solver parity: `SOLVER_PARITY=1 npx vitest run src/lib/solverParity.test.js` (bash) or `$env:SOLVER_PARITY=1; npx vitest run ...` (PowerShell). No npm script — repo has no `cross-env`, and `VAR=1` scripts no-op under Windows cmd.
- Netlify deploys master (`netlify.toml`: build `npm run build`, publish `dist`, SPA redirect). Site: residentscheduling.netlify.app.
- Supabase SQL: `npx supabase db query --linked -f <file>` (CLI not on PATH). `--linked` follows `supabase/.temp/`, NOT the dashboard's selected project — a migration once hit the wrong sibling project that way.

## Layout & stack
- Public GitHub repo `picklepilk/resident-scheduler`. **Never commit real resident names, rosters, or email addresses** — all real data enters via the import features into localStorage only. Allowlist emails/bootstrap SQL are typed into the SQL editor as data; committed `supabase/*.sql` carry placeholders only. `.gitignore` covers `*-resume.txt` transcripts — keep those entries.
- React 19 + Vite 6 + Tailwind. `xlsx` installed from SheetJS CDN tarball (`https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz` in package.json), **never `npm install xlsx`** — registry build frozen at 0.18.5 with unpatched CVEs.
- `jspdf-autotable@3.8.4` default-export interop is broken under esbuild/Rollup: use `import 'jspdf-autotable'` (side effect) + `doc.autoTable({...})` instance form, never `autoTable(doc, {...})`. `npm run build` succeeding does NOT catch this (bundling doesn't execute); verify with a standalone esbuild bundle before upgrading (em-scheduler pins `^5.0.7` and uses the function form successfully).
- **Almost all scheduling logic lives in `src/ResidentScheduler.jsx` (~8,300+ lines).** Grep for `// ─── SECTION ───` markers or function names, not line numbers. Grep before assuming any helper unused — no module boundaries.
- `src/lib/*` modules are pure and **may never import `ResidentScheduler.jsx`** (that's why lib math like `coverageComposition.js`, `journalClub.js`, `qgenda.js` lives there).
- Auth/day-off-request surface is deliberately outside the big file: `main.jsx` (route split: `/requests` → `ResidentRequestsApp`, else `AppGate`), `AppGate.jsx`, `supabaseClient.js`, `RequestsTab.jsx`, `residentRequests/*`. **Nothing under `residentRequests/` imports `ResidentScheduler.jsx`** — it fetches its own data from the shared `res_state` row.
- Sibling project `../em-scheduler` (same author/domain): check its CLAUDE.md for prior fixes before re-deriving scheduling/export/matching patterns.
- **TDZ hazard**: module-level `const` referencing a later `const` throws at page load; `npm run build` won't catch it. `RULE_NOTES` prose deliberately hardcodes numbers duplicating `NIGHT_RULES`/`JC_MAX_PER_AY`/`TRAUMA_PEDS_SPLIT` for this reason — change one, update matching prose.

## Persistence, cloud sync, demo sandbox
- `useLocalStorage` backs state slots under `res_*` keys. Nine ride `LS_BACKUP_KEYS` (roster, current block, blocks history, eligibility overrides, AY data, app settings, day rules, coverage, tab order) — Settings backup/restore AND cloud sync both derive from that list. **A new `res_*` key must be added to `LS_BACKUP_KEYS` + `syncBindings`** or it silently won't round-trip (forgetting `syncBindings` throws; forgetting the list is silent loss).
- Device-local keys deliberately EXCLUDED from `LS_BACKUP_KEYS` (viewer prefs, never synced): `res_dark_mode`, `res_demo_mode`, `res_whats_new_seen`, `res_ui_prefs`.
- Everything read from backup/cloud/localStorage is untrusted shape — guard like `reconcileTabOrder` (`Array.isArray`), `normalizeCoverageEntry` (legacy single-number → `{min,max}`), `offRequestEntryFor`.
- Cloud sync (`// ─── SUPABASE SYNC ───`): hand-rolled PostgREST client `sbFetch` (15s AbortController timeout), no supabase-js. Gated by `SUPABASE_ENABLED` from `%VITE_*%` HTML-token env injection; `isUnresolvedToken` treats a literal unresolved `%VITE_...%` as unconfigured (clean local-only fallback). One `res_state` table, row `id:'main'` holds the whole document as one jsonb blob; last-write-wins, no merge — accepted.
- **`dbReady` gates all cloud writes and stays false if mount-time load fails** — a device that never read the cloud must not overwrite it. Debounced (1.5s) save compares against `cloudBaselineRef`; body lives in `saveCloudNow()`, `flushPendingCloudSave()` awaits both a pending timer AND an in-flight save (`savePromiseRef`).
- `SettingsTab.clearAll()`/`importData()`: cloud op must succeed FIRST, then local wipe/write + reload; both set `syncSuspended` so the debounced save can't race. `clearAll` deletes main row first, demo row second/best-effort. Both early-return with a toast in demo mode.
- Demo sandbox: isolation by PHYSICAL key — `physKey()` rewrites `res_` → `res_demo_` when `demoMode`; cloud mirror row `id:'demo'` via optional `rowId` param (real row is the default everywhere). `demoMode` read once per mount; every enter/exit/resume/delete sets the flag then `window.location.reload()`. `enterDemoFresh` copies live data cloud-first. `deleteDemo` deletes the demo row twice (defense vs raced upsert) before removing local keys. Every action calls `flushPendingCloudSave()` first. Export in demo is guarded on `dbReady`.
- One-shot mount migrations that store a marker (e.g. `migratePedNightAssignments` / `res_pednfm_migrated`) must gate on `dbReady`, not `[]` — else they migrate the pre-overlay copy, burn the marker, and get overwritten by the still-unmigrated cloud row. Markerless prune effects (LEGACY defaults) don't need the gate.
- Feedback widget: separate `feedback` table, insert-only RLS for anon, `app_name:'resident-scheduler'` (table shared with em-scheduler). Crash auto-reports capped 5/session. Read path: password-gated Feedback tab → `netlify/functions/feedback-admin.js` using `SUPABASE_SERVICE_ROLE_KEY` + `FEEDBACK_ADMIN_PASSWORD` (server-only Netlify env vars, never `VITE_`-prefixed).
- Jeopardy/sick-call ledger lives in `appSettings.jeopardyLog`, **NOT its own `res_*` key — load-bearing**: an older bundle's whole-document cloud write would silently drop a 10th key, but round-trips unknown `appSettings` sub-keys. Don't "clean up" by promoting it.

## Auth, roles, RLS
- Gated on `AUTH_ENABLED` (`src/supabaseClient.js`): all three env vars set. Missing → dev build falls through unauthenticated (deliberate convenience); **production build fails closed** (`AuthMisconfigured`). Keep the asymmetry.
- Three roles (`profiles.role`, CHECK-constrained): `pending` (zero access, default) → `resident` → `admin`. No 'chief' role — any stray `'chief'` string is leftover, should be `'admin'`.
- **RLS is the security boundary; UI gates are convenience.** `is_admin()` SECURITY DEFINER helper exists because an inline profiles subquery inside a profiles policy recurses — don't inline it. Column-level rules live in four BEFORE triggers (`enforce_cancel_only_status`, `enforce_request_identity_immutable`, `enforce_resident_id_immutable`, `enforce_profile_role_change_rules`); self-promotion impossible by construction. Every resident-facing policy must fold `role <> 'pending'` in — a client-only pending check once allowed impersonation via `/requests` (`migrate_block_pending_account_access.sql` is the reference pattern).
- Admin email allowlist: promotion keys off `auth.jwt()->>'email'`, **never `new.email`** (client-controlled); membership check is zero-argument (no enumeration oracle); table has RLS on with no policies (unreachable from sessions); affects first row creation only.
- Domain restriction is a Supabase Auth Hook (`restrict_signup_domain`) that does nothing until wired in the dashboard (Authentication → Hooks → Before User Created) — verify with a real `POST {url}/auth/v1/otp` (expect 403), don't assume.
- `supabase/*.sql` are run by hand, in order: `day_off_requests.sql` is the kept-current fresh-install baseline; `migrate_*.sql` are one-time deltas. Schema change = update baseline AND add a companion migrate file.
- Accepted gap: `blockLookup.js` pulls the whole `res_state` blob (schedule included) to the resident's browser; "residents never see schedule" is UI-enforced only.

## Shift catalog & data model
- `SHIFTS`/`SHIFT_TIMING`/`SHIFT_MAP`/`SHIFT_AREAS`/`SHIFT_TYPES`/`SHIFT_DOW` at top of the big file. Shift ids are `AREA-TYPE` (`POD-D`, `MT-N`; exceptions `PED-S`, `PED-N-FM`); **nothing parses ids by splitting on `-` — don't introduce that.**
- Adding a shift: add `SHIFT_TIMING` entry (else rest validation silently skips it) AND `DEFAULT_COVERAGE_MINMAX` entry (`coverage.test.js` enforces catalog-wide; a missing entry silently demands 1 body/day ≈ 28 phantom unfilled slots).
- **Coverage is `{min,max}`**, not one number: generator fills to min (hard), tops up toward max only for under-target residents (soft cap). Coverage is deliberately NOT day-of-week-dependent, with exactly one exception: `DOW_COVERAGE_MAX_OVERRIDE` raises POD max to 3 on Mon/Tue (via `getCoverageFor`'s `dow` param). `PED-S` weekday existence is `SHIFT_DOW`, a separate mechanism.
- `getShiftTarget` resolution ends in a **single tail return** applying `targetDelta` — never add early returns (buy-downs would be silently ignored). A delta that zeroes the target returns **`null`, not `0`** (`0 != null` would keep the resident in fairness spread as a maximal outlier). `computeQualityMetrics`' second `baselineTargets` map must keep its per-resident `?? target` fallback. Buy-downs are DELTAs (survive `SHIFT_TARGETS` changes); `ImportMatrixModal` MERGES assignment records (replace would wipe deltas/isChief).
- `BLOCK_TARGETS.EM_HOME_2__EM_EMS/EM_TOX = 7` (flat 19 unreachable under the 2-weekday gate; `blockTargetReachability.test.js` asserts generically). These rotations get a strong soft non-PED penalty (`emEmsToxNonPedsPenalty`), NOT a hard PEDS-only strip (measured to cost real coverage).
- Chief's call-in/payback convention: per-resident shift counts read off real historical schedules must never derive/validate targets; small over/under is expected noise.
- Vacation (`vacationDates`) vs approved-off (`approvedDatesOff`): behave identically (hard off) but stay distinct fields (VAC teal vs OFF orange markers). `offRequestNotes` (reason/note stamped at approval time by `RequestsTab.decide()`) rides `res_em_roster`; `offReasonText` is the single reader, 200-char cap.
- Off-service residents live in `block.offServiceResidents[]` with `availabilityMode: 'full'|'ranges'|'days'` (checked by `isAvailableOnDate`). Resident-level fields inside block/roster objects need no new backup key.
- `offServiceWindowTargetDelta` is a thin wrapper over `offServiceWindowStatus` — non-display consumers must call the wrapper, which collapses zero delta to `null` via `status && status.delta !== 0 ? status.delta : null` (NOT `status?.delta ?? null` — `0 ?? null` is `0`, a bogus target adjustment).
- `blocksHistory` snapshots carry `published` — `saveBlock` must preserve an existing snapshot's flag or re-saving un-publishes. Published-only consumers: JC cap counting, AY carryover. `computeBuyDownsApplied` deliberately counts unpublished too (and skips the live block's own snapshot).
- BAMC residents with no `blockType` default to `'EM'` rotation in `isSchedulable` (read-time fix; Off-Service tab never assigns one).
- Chief roles: global `resident.chiefRole` (`academic`/`admin`/`scheduling`), any → 16-shift target; only `academic` bars Tue eve/night (checked on `chiefRole` directly, NOT the legacy `effectiveChiefRole` fallback). `effectiveChiefRole` is read-time-only compat for old `isChief`.

## Scheduling rules (enforced in getEligibleShifts / validateAll / generator)
- **Circadian** (`NIGHT_RULES` 4-6-6): eve→day next day (and reverse) hard errors; max 6 nights/block (`isNightOnlyResident` FM-3 exempt); ≥24h post-night rest before day/eve OR Grand Rounds is soft `rule:'postNightRest'`, checked BOTH directions. Hard circadian + GR-gap checks run in `validateAll` regardless of `appSettings.enforceRest` (that toggle gates only the pairwise rest-hours check). Rolling 80h/wk pro-rated cap → generator reason `'hoursCapped'`.
- **Trauma**: TRAUMA-D/N hard-clamped max 1 in generator regardless of editor. Hard ≤2 TRAUMA-N per contiguous night run (`traumaRunCapped`; `validateAll` error; solver rule 43, never relaxed). Soft: `traumaSecondInRun`/`traumaMidRun`/`nightDurationAlternation` (alternation exempt at 12h-window boundaries via `alternationExemptDates`).
- **Night-run shape**: scoring stopped penalizing runs 2–6 (only isolated singles cost); `validateAll`'s advisory "isolated night stint" warning still fires below `minRun` 5 — deliberately divergent, don't conflate. Soft `secondRestDay` prefers 2nd day off after 3+ night runs.
- **Max 6 consecutive work days** (`MAX_CONSECUTIVE_WORK_DAYS`, strict ACGME): a day counts if a shift is assigned (current block OR prior block's tail via `prevBlockTailSchedules`), OR it's the resident's GR weekday (`grWorkDow`: EM_HOME Wed, EM_BAMC Thu), OR a JC presenting date — UNLESS the date is vacation/approved-off. Boolean per date (working GR day = one day). Shared by validator, generator, picker (`prevTail` threaded from `ScheduleGrid`). A run with zero actual shifts (`runHasShift` false) raises no error.
- **Journal Club** (`src/lib/journalClub.js`): 18:00–21:00; "worked" derived from `SHIFT_TIMING` overlap (`shiftOverlapsJC`), never a hand list. Max 3/AY counted across Published blocks + live. JC dates chief-editable per AY (`ayData[AY].jcDates`): absent = derive first Tuesdays; explicit `[]` honored. Consumers use `resolveJcDates`/`jcDatesInRange`/`isJcDate`/`isJcDateAnyAy` — never re-derive. `ayWindowFor().end` is EXCLUSIVE; blank block AY falls back to `getAcademicYearFor(startDate)`; `validateAll` scopes `jcPresentDates` to the AY window. Generator hoists a JC-date Set per run. Presenter's overlapping shifts hard-stripped that day.
- **Holidays** (`src/lib/holidays.js`, `ayData[AY].holidays`): named multi-day entries. **Absent config derives NOTHING** (deliberate opposite of jcDates); `defaultUsHolidays` only behind "Add US defaults" (merges by start date). "Worked" = shift STARTS on the holiday date. Time off on a holiday = unavailable, not spared (count 0 steers next holiday toward them). `holidaySpread` coeff 8 in the existing last vector slot; `holidayEquity` tiny fill-time preference; `holidayYearly` maintained at the same 3 counter sites as `traumaNightYearly` (exact inverse pair with repair's revert). Card renders nothing when unconfigured; no-config generation is bit-for-bit unchanged (tested).
- **GR lecture dates** (`grLectureDates`): no eve/night the day before — hard-stripped + validated; dates validated against `grWorkDow`. M&M dates merge into this same field.
- **Seniority**: FLEX soft (`{primary:2,fallback:3}`, junior beats unfilled, `report.seniorGaps`). **POD hard** — staffed POD without PGY-3 is a `validateAll` ERROR unless it's the resident's own 3rd Wellness Wednesday (`podWellnessSubstituteAllowed`); generator's POD branch enforces it too (`'pgy3Required'` unfilled reason). **Wednesday DAY shifts exempt from both** (`seniorCompositionExempt` — GR makes EM seniors structurally absent; off-service/APPs cover). That helper has FOUR call sites that must stay in lockstep: `validateAll` senior loop, `fillDayPass` POD branch, `fillDayPass` FLEX branch, `narrowForSeniority`/`podStillSatisfied`.
- **EM-count composition (soft, both engines)**: POD@2 wants 2 EM, POD@3 wants ≥2, FLEX ≥1 (`podEmComposition`/`flexEmComposition` score terms + `validateAll` warnings). `narrowForPgyGate` pool-restricts POD PGY-2 (FLEX PGY-3) while the primary PGY can cover, falls back with `report.pgyFallbacks`; EM_HOME only, never EM_BAMC; validator uses a deliberately conservative proxy (warns only when a primary is already covering).
- **Wellness Wednesdays**: block-relative Nth Wednesday per PGY (computed day rules) — `ctx.blockStart` must reach EVERY `getEligibleShifts` call site (a grid caller once omitted `ctx` and silently no-op'd this).
- **Jeopardy never collides with a clinical shift** (hard under `'warn'` AND `'block'` policy; `'off'` fully silent): `candidatePool` excludes (`'jeopardyConflict'`), `fillJeopardy` excludes already-scheduled (`'allScheduled'` vs `'allUnavailable'`), `validateAll`/`cellViolations` escalate to error. `SCORE_WEIGHTS.jeopardy` was removed as unreachable. **Off-service residents have no jeopardy**: `isJeopardyDate` gates on category `EM_HOME`/`EM_BAMC` (read-time ignore, not migration); jeopardy editors removed from off-service surfaces. Deferred (documented, unmodeled): chief runs ADMIN/METRO/ELECTIVE as multi-day jeopardy streaks + token end-of-block shift.
- **Trauma/Peds split** (`TRAUMA_PEDS_SPLIT` {trauma:8, peds:11}): two protected sub-targets via per-resident sub-caps in `candidatePool`, not one 19. `allowSplitPedsNights` lets the peds half take PED-N (9h only, never PED-N12); trauma half stays Trauma-Day-only unconditionally. **Default flipped to true** (`?? true` at all three read sites — old backups with no key now get ON). `pedsInternNightDeficit` targets 5 PED-N per split intern in both engines.
- **PED-N split (2026-08-18)**: `PED-N` 19:00–04:00, all 7 nights, owners EM_HOME_1/2/3, EM_BAMC_1, FM_1, PEDS_2/3 (Round 2b removed the old Thu–Sun gate). `PED-N-FM` 23:00–08:00, FM_3 only, Mon/Tue/Wed. Both `{min:0,max:1}`, both `type:'night'`. `PED_GUARD_LEGITIMATE_OWNER` is DERIVED from `BASE_ELIGIBILITY` for PED-N/PED-N-FM/PED-S — grant eligibility there, never hand-edit the guard. Consequences that are live: `shiftOverlapsJC('PED-N')` is now true (PED-N on a JC Tuesday counts as worked JC); night→eve-next-day is covered by the widened `postNightRest`; legacy FM `PED-N` cells were renamed via `migratePedNightAssignments` (dbReady-gated) + `LEGACY_SHIFT_ID_RENAMES` in `eligibilityOverrides.js`. PED-S similarly now all 7 days, multi-owner.
- **EM/EMS ↔ EM/TOX weekday windows swap on 2026-08-01**: both variants live in `DEFAULT_DAY_RULES.EM_HOME_2.shiftGates` distinguished by `activeWhen` (evaluated against block startDate by `gateActiveForBlock`) — don't "clean up" into one gate. EM_TOX gets soft +8 for PED-E.
- **Soft Rule Priority** (`appSettings.rulePriority`): chief-orderable `coverageMin`/`seniorComposition`/`postNightRest`. Default ranks coverage first (rest/senior compromises recorded); reordering protects the rule instead (`'restProtected'`/`'seniorProtected'` unfilled reasons). Rides `res_app_settings`, `normalizeRulePriority` handles old backups.
- Peds Wednesdays: PEDS_1/PEDS_3 `fullBlockDays:[3]`. Advocacy-days feature REMOVED — stale `specialDays.advocacyDays` in old snapshots is never read; don't migrate, don't resurrect.
- IM_2: Tue only-day, Wed only-night.

## 12-hour shift windows
`src/lib/coverage.js`, `ayData[AY].twelveHourWindows`, edited via `TwelveHourWindowsEditor` on Dashboard. The 8 ids (`POD/MT/FLEX/PED × -D12/-N12`) staff only inside chief-defined windows (`mode:'replace'|'add'`, optional per-window coverage). `resolveTwelveHourWindows`: explicit array wins (explicit `[]` = none); absent → `implicitConferenceWindows` (one replace POD/MT/FLEX window per ACEP/AAEM/SAEM range; ITE excluded). Don't reintroduce a second answer to "does this date run 12h".
- **`twelveHourStateFor` NEVER returns null** — always `{replaceAreas, addAreas, covOverride}` with empty sets. `getCoverageFor`'s 4th param is that state object; `undefined` = "no date context" → base numbers. A null would make every 12h minimum live on every date (was a real latent bug worth 280 phantom coverage misses in fixtures).
- Resolution inside `getCoverageFor`: (1) normal id in `replaceAreas` → `{0,0}` returned immediately (before TRAUMA clamp / dow raise); (2) 12h id in no window → `{0,0}` EXCEPT PED-D12/PED-N12 (fall through, year-round opt-in works); (3) 12h id in window → `covOverride` → explicitly-present global `coverage[sid]` → `replace ? DEFAULT_COVERAGE : {0,0}`. `twelveHourAllows` shared with `getEligibleShifts` step 8, but each caller owns its own `undefined` behavior (legitimately opposite). Generator resolves per-date via memoizing closure `conf12For` — never a prebuilt map (a miss = phantom minimums). Rules-tab totals exclude 12h ids.

## Generator
- `generateSchedule()`: coverage-driven, three passes via `fillDayPass` — `'min'` for everything except TRAUMA-D, then TRAUMA-D alone (PGY-1 trauma-day is deliberately the final min step — don't collapse), then `'optional'` top-up (empty pool silently skipped, max is a cap). Candidate pool recomputed fresh per slot — a cached pool once caused double-booking; the decision path must never go through a cache. Never overwrites non-empty cells (`keptCells` — covers manual entries and partial-regenerate identically).
- **Fresh MRV**: greedy re-pick of most-constrained remaining slot after every placement. Counts maintained incrementally (exact ONLY because every `candidatePool` filter reads per-resident state — a new cross-resident filter silently degrades the ordering); the cache is a SORT KEY ONLY; the count is composition-aware (effective sub-pool for FLEX/POD seniority) — that's where the measured win is, don't drop to raw pool size. Ties resolve to earliest original slot (determinism preserved).
- `generateScheduleBest()`: 20 seeded attempts (`baseSeed + i*0x9E3779B9`, `mulberry32` rng injected into `score()`'s tie-break), picked by `betterQuality` — **lexicographic** `(validateAll errors, export-blocking warnings, quality vector)`, never a weighted scalar. Any result replayable: `generateSchedule({...args, rng: mulberry32(report.seed)})`. Solver `FEASIBLE` results are NOT replayable — the returned schedule is the record.
- **Repair pass** (`repair:true`, run once on the winning seed, kept only on strict improvement): Phase 1 same-day/cross-day swaps for unfilled mins, Phase 2 rest-compromise swaps, Phase 3 senior swaps, Phase 4 bounded depth-2 ejection chains. Every move transactional (candidatePool re-check, coverage-min floor, exact revert) and narrowed by `narrowForSeniority`/`podStillSatisfied` (without them repair manufactured hard errors). Pool budget 300 (P1–3) + 200 (P4) — deliberately not shared (P1 exhausts any shared budget). Post-repair report arrays rebuilt from the final schedule, scoped to generated cells only; the quality scorer reads the WHOLE schedule including kept cells.
- **`SCORE_WEIGHTS`/`SCORE_TIERS`** (exported; `scoreWeights.test.js`): every weight classified STRUCTURAL or PREFERENCE; test is a RATCHET (bands can't grow past ceilings, every weight must be classified). Known-inert inversion: preference bands can exceed a shift's deficit worth, but `candidatePool`'s `allAtTarget` filter enforces target fairness upstream — if that filter is ever loosened, revisit (documented A/B rejected a rescale).
- Work-shape scoring: fragmentation charged only beyond `ceil(worked/6)` runs (6-day cap REQUIRES ≥3 runs at target 18); joins the existing last vector slot at 0.5 — never a 5th slot.
- **Area spread** (`SCORE_WEIGHTS.areaShare` 15 STRUCTURAL, DAY/EVE ONLY + `areaSpread` metric): `mixShare` only buckets day/eve/night, so POD-E/MT-E/FLEX-E are one indistinguishable "eve" and area concentration went unscored (measured: residents eligible for all 5 areas finishing an 18-shift block 100% in one area). `areaCount` is maintained at the SAME four sites as `nightAreaCount` (seed, `fillDayPass` commit, repair assign/unassign). **Nights are exempt** — they already have `nightAreaDiversity`, pinned at weight 2 so area spread can never compete with `nightCluster`(40); including nights tripped `chiefBenchmark`'s isolated-single-night-run guard (25 vs 23 ceiling). Weight 15 (not the concentration-optimal 25) because 25 still fails that guard at 24. **The `areaContinuity > 0` gate is load-bearing** — ungated, the term opposes `workShapePenalty`'s within-run area-churn charge and regresses it, the way the reverted Phase 2.3 type-churn term did; gated, it speaks only when a NEW run starts, so continuity governs WITHIN a run and areaShare ACROSS runs. `areaSpread` (excess over `AREA_CONCENTRATION_FLOOR` 0.5) joins the existing last vector slot at 2 — never a 5th slot. A finer per-shift-id twin was built and A/B rejected (inert on 2 of 3 fixtures; the fill-time half regressed restCompromises).
- **AY carryover** (`computeAyPriorTotals`): spreads blended with prior AY totals from PUBLISHED snapshots only, capped at 6 blocks. Strict no-op on empty history; a resident with no history is EXCLUDED from the AY population, never zeroed (zero = maximally under-worked = hammers the newest resident).
- Override capture: hand-edits to a generated schedule logged into `block.overrideLog` via `updateBlockTracked` ONLY (the single mutation choke point). Two guards: previous schedule must have a `generationReport`, and a generation itself (report identity change) is skipped. Cap 500. Report-only — nothing reads it back into generation.
- Readiness gate (`checkGenerateReadiness`): warns (with Generate Anyway) on empty relevant special-day lists + JC presenter gaps (`jcPresentersFor` shared with the planner card).
- Progress overlay: `startGenProgress`/`stopGenProgress` in a `finally`; `yieldToPaint()` (double rAF) awaited before every synchronous generator call so the stage label paints. z-100.

## CP-SAT solver service (optional second engine)
`solver-service/` — Python/FastAPI OR-Tools; contract in `solver-service/docs/PAYLOAD_SCHEMA.md`. Optional: `VITE_SOLVER_URL` unset → `SOLVER_ENABLED` false, app unchanged. Chief kill switch `appSettings.useSolverService` read as `!== false`. **The app resolves ALL policy into the payload; the solver only solves.**
- Seams in the big file: `buildSolverPayload()` (same args shape as `generateSchedule`), `mapSolverResult()` (back to `{schedule, report}`), `generateViaSolverOrLocal()` — the ONLY solver-vs-local decision point, falls back to `generateScheduleBest` on any failure. `src/lib/solverClient.js` is the fetch wrapper (long timeout, solves legitimately run tens of seconds).
- **Payload gotcha (recurred once)**: an eligibility carve-out enforced only in the generator's `candidatePool` (not `getEligibleShifts`) must ALSO be filtered in `buildSolverPayload` — e.g. jeopardy dates excluded whenever policy `!== 'off'` (the solver has no human-in-the-loop; `validateAll` hard-errors the collision under `'warn'` too).
- Round 2b optional fields (`traumaNightShiftIds`, `pedsSplitInternIds`, `pedsInternNightTarget:5`, `alternationExemptDates`, `emResidentIds`, `emPgy2/3ResidentIds`…) all default to no-ops server-side; `emPgy2/3ResidentIds` are EM_HOME-only, mirroring `narrowForPgyGate`.
- Feasibility report (solver `mode:'relaxed'`): "BEST EFFORT" banner in `ScheduleGrid`, `FeasibilityReportCard` on Violations tab, `relaxedCellSet` dashed-amber cell rings (distinct from `violMap`'s solid red).
- `chiefBenchmark.json` fixture is ANONYMIZED (R-labels only — public repo); its tests assert match-or-beat the chief's own hand-built block.

## UI conventions
- **Dark mode**: override stylesheet in `index.css` (`.dark` sheet), NOT Tailwind `dark:` variants (thousands of class strings). Wrapped in `@media screen` so print/PDF stays light. Exempt on purpose: solid `-500/600/700` button backgrounds with `text-white`, vivid rings/outlines, modal scrims, `SidebarNav`/`DAY_MARKERS.dark` (sidebar is solid dark-navy in every theme). Auth/requests surfaces render inside AppGate's `.dark` wrapper and need the same treatment.
- **`DAY_MARKERS`**: single style table for GR/JC/WW/OFF/VAC/J + pending-R badge across all seven render sites. `onShift` variant is solid `bg-white` + colored ring + `-700` text — **never an alpha tint** (chip background bleeds through). New/changed marker = edit this table, never inline classes.
- **Schedule grid**: sticky header/footer/name-column only work because the scroll container is `overflow-auto` with a bounded `maxHeight` — don't remove the height bound. Z-ladder: cells 10 → header/footer 20 → corner cells 30 (INLINE `zIndex` — `.grid-sticky` is unlayered CSS and beats `@layer utilities` classes) → app header 50 → fullscreen 60 → progress overlay 100 → toast 200. Fullscreen is an in-app `fixed inset-0` overlay, not `requestFullscreen()`.
- **Grid readability**: zoom 50–150% applied as CSS `zoom`, **never `transform: scale`** (breaks every sticky axis); the `maxHeight` calc divides the zoom back out. All three input paths (buttons/wheel/pinch) share ONE clamp inside `setGridZoom`. Column width: `CELL_W = CELL_W_BASE + gridColExtra` local to `ScheduleGrid`. Both persist in `res_ui_prefs` (`normalizeUiPrefs`; `clampGridZoom` typeof-checks, no `Number()` coercion — `Number(true)` is 1). Two-tier header: week band height set on the band ROW (border-box), second tier sticks at `top: WEEK_BAND_H`; bands are MONDAY-started (blocks start Monday; Sunday-start splits the weekend). Weekend cells `bg-slate-100`; `border-l-2` marks Mondays.
- **Cell locking**: `block.lockedCells` inside the block (rides existing persistence); undo pairs `{schedule, lockedCells}`; generator knows nothing about locks (`runPartialRegenerate` clears only unlocked, `keptCells` protects the rest); every bulk lock action = ONE functional `updateBlockTracked` (looping per-cell floods undo); chip `draggable` disabled while lock-paint is on.
- `computeCoverageByDate` is shared by grid footer, Dashboard tiles, Calendar view — never fork it; it reads only `r.id` (works on stub snapshot rosters). `cellViolations` shared by picker + drag-drop (both sides validated against `scheduleClearing`-adjusted state; violations open `DragConfirmModal`). Root `issues`/`issueCounts` memo = ONE `validateAll` pass for all consumers.
- Dashboard is the landing tab (Home tab GONE — read old "Home tab" references as Dashboard). Hosts `BlockCalendarSection` (AY timeline of snapshots + coverage heatmaps), Current Block editor, `AYConferenceEditor`, JC/Holiday date editors, `JournalClubPlanner` (writes `jcPresentDates` via functional `setEmRoster` by id), Special Days, stat cards, `JeopardySickCallsCard`.
- **What's New**: `CHANGELOG` newest-first; change `id` only for interruption-worthy releases; `res_whats_new_seen` device-local; `markChangelogSeen()` is the single writer; `WhatsNewTab` freezes its unseen set at mount so New pills survive the visit that clears them; `renderChangelogText` shared (bold-only markup, deliberate).
- `TimeOffModal` paint math is pure in `src/lib/dateSetPaint.js`; deliberately NOT wired into `ResidentForm` (nested-modal unverified). Requests tab is the only tab component outside the big file; it re-checks its own session/role.
- Coverage tab math lives in `src/lib/coverageComposition.js`; reproduces `computeCoverageByDate`'s two guards (skip `SHIFT_DOW`-inactive, resolve `twelveHourStateFor` once per date).

## Rule-default migration (required whenever defaults change)
`getEffectiveDayRules`/`getEffectiveEligibility` replace defaults WHOLESALE with chief overrides — an override equal to a superseded default masks the fix forever. **When correcting `DEFAULT_DAY_RULES`/`BASE_ELIGIBILITY`: push the old shape onto that key's array in `LEGACY_DAY_RULE_DEFAULTS`/`LEGACY_ELIGIBILITY_DEFAULTS`** (arrays accumulate one snapshot per correction) — the mount prune drops overrides deep-equal to ANY snapshot; genuinely customized overrides get an amber review badge (`DAY_RULE_DEFAULTS_CHANGED`, derived from the maps' keys).

### Eligibility overrides are a DIFF, not a snapshot
`res_eligibility_overrides` stores `{added, removed}` per key (`src/lib/eligibilityOverrides.js`). The old wholesale-list format made later-added shift ids invisible forever (shipped as a real silent ACEP outage — 12h shifts unassignable under old rotation overrides, which `LEGACY_*` can't reach since it's keyed `CATEGORY_PGY` and rotation keys are `CATEGORY_PGY__ROTATION`). **Don't "simplify" back to a list.**
- Both shapes read forever through `normalizeEligibilityOverride`; legacy arrays get `backfillLaterAddedShiftIds` FIRST (restores a 12h id only when current base grants it AND the snapshot lists the matching 9h sibling).
- One-time mount migration order is load-bearing: prune legacy-equal overrides FIRST, then convert category keys before rotation keys (rotation base = parent's effective list). Empty diff deletes the key.
- `eligBaseFor`: category key → `BASE_ELIGIBILITY`; rotation key → parent's effective list (category edits now flow through un-overridden rotation rows). `ShiftMatrixTab` uses the same helpers. `stripPedGuardedShifts` runs AFTER resolution — PED guards beat any override.

## When editing
- Grep before assuming a helper unused. Run `npm test` for lib/generator changes; `npm run dev` + sample generation for UI changes.
- New `getEligibleShifts` call site: always pass `ctx = {blockStart: block.startDate, ...}` (`forGenerator` gates `scope:'generator'` restrictions).
- New shift: `SHIFTS` + `SHIFT_TIMING` + `DEFAULT_COVERAGE_MINMAX`. New marker: `DAY_MARKERS`. New `res_*` key: `LS_BACKUP_KEYS` + `syncBindings`. New rule default correction: `LEGACY_*_DEFAULTS`. New candidatePool-only exclusion: mirror in `buildSolverPayload`.
