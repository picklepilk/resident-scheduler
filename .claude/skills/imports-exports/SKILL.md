## Imports & exports
- **Master Matrix** (`ImportMatrixModal`, Dashboard): sheets detected by CONTENT not tab name; two home-sheet shapes (legacy PGY markers, or grouped tracks with PGY inferred from `EM_HOME_BLOCK_TYPES_BY_PGY` exclusivity); off-service triples found by scanning for the date-range cell (offsets drift — no fixed columns). Two date-range parsers (`parseSequentialDateRange` home, `parseDateRangeInAY` off-service) solve different year-inference problems — don't merge. Writes ONLY `emRoster` (merge) + `blocksHistory` (`blk_import_<start>`, re-upload updates in place) — never the live block.
- **Off-service `availableRanges` (2026-10-14 fix)**: `commit()`'s off-service builder is extracted as `buildOffServiceResidentsForBlock(offRows, b)` (exported from `ResidentScheduler.jsx`). It stores each resident's `availableRanges` as the sheet's REAL, UNCLAMPED `{o.start, o.end}` — their actual ER rotation window, which may run past either edge of the EM block being imported into. It used to clamp to `[b.start, b.end]`, which silently defeated `offServiceWindowStatus`'s straddling-window pro-rate/measure math on every real import (`totalWindowDays` always equaled `overlapDays`). `isAvailableOnDate` (the only other `availableRanges` consumer) is always queried with dates drawn from the currently-open block's own date list, so a wider stored range can never leak availability onto an out-of-block date — safe to widen. A resident whose rotation spans N blocks gets N records (fresh uuid per block, same sheet row) with the identical unclamped range; cross-block matching in `offServiceWindowStatus` falls back to normalized name since ids are never shared across blocks. Existing pre-fix `blocksHistory` snapshots keep their old clamped ranges (no migration) — `offServiceWindowStatus` degrades gracefully to its "fully inside this block" null, not a crash; only a re-import picks up the real window. The 3-call-site straddle badge (`OffServiceStraddleBadge`, next to `offServiceWindowStatus` in `ResidentScheduler.jsx`) and its pure day-math (`src/lib/offServiceWindow.js`) are display-only and don't touch this builder.
- **Vacation/Lecture importers** (EM Residents tab): tolerant name matching via `src/lib/nameMatch.js` (`matchRosterByName` etc. — the ONE shared matcher, don't grow a second); ambiguous matches never auto-commit. Lecture+M&M both merge into `grLectureDates`; JC dates validated with `isJcDateAnyAy` (imported dates span AYs), mismatches flagged not blocked.
- **QGenda export** (`src/lib/qgenda.js`, pure): `QGENDA_TASKS` = our id → the chief's REAL task names, corrected 2026-08-22 against a real export — trailing hour ranges, leading `*` on Peds tasks, odd casing are all EXACT; `qgenda.test.js` pins all 16 strings and re-derives hour suffixes from `SHIFT_TIMING`. **Don't tidy.** `TRAUMA-D` is a function (PGY-1 → "Trauma Day-Intern"). The eight 12h ids deliberately absent → fallback label + `exportConfirm` warning (never blank, never silent skip). Column names live in `QGENDA_VARIANTS[*].columns` as data. Chief overrides in `appSettings` (sparse), per-resident `qgendaStaffId`. `downloadCSV`: CRLF + trailing terminator; BOM on for human Grid CSV, OFF for QGenda; `quoteMode:'minimal'`. Demo guard tests `kind === 'qgenda'` by EQUALITY — variant is a second arg, never folded into the kind string. `Start`/`End` derived from `SHIFT_TIMING` numbers; `EndDate` rolls to next day past midnight; dates via `qgendaDate()` `M/d/yyyy` (QGenda rejects 2-digit years) — `prettyDate` stays 2-digit for its ~25 on-screen call sites.
- **QGenda import** (`src/lib/qgendaImport.js` + `ImportQGendaModal`, Dashboard): `QGENDA_TASK_TO_SHIFT` DERIVED from `QGENDA_TASKS` (normalized keys — import tolerates casing drift, export stays byte-exact). Rows found by content (day-number header with weekday row beneath; person rows need a non-blank date cell). Month/year walk cross-checked against the weekday row — a `dowMismatch` disables the import button. Dates built by string concat, never `toDateStr(new Date(...))` (UTC shift). `Res_Call PGY*` → `jeopardyDates`, never `block.schedule` (would manufacture hard errors). Nothing invented: unmatched names get a category+PGY picker, pre-filled only where the file revealed one; ambiguous matches reported. Writes snapshot `blk_qgenda_<start>` only, carrying forward `emBlockAssignments`/`offServiceResidents` from a same-start snapshot (whose off-service residents also join the matching pool). Unrecognized tasks reported with counts.
- **PDF** (`// ─── PDF EXPORT ───`): matrix on landscape A3; per-resident pages with Notes (OFF reason ≤40 chars — resident's own reason, never the chief's decision note; `shiftGapsFor` gap hours). Demo banner via `didDrawPage` + `margin.top` = `PDF_DEMO_BANNER_H` (startY alone only fixes page 1).
- CSV/PDF/QGenda all route through `requestExport`/`exportConfirm` error gate.
- **Academic Schedule importer** (`src/lib/academicSchedule.js` parse + `academicImportPlan.js` plan/apply, `ImportAcademicModal`, Dashboard menu): `.docx` unzipped with `fflate` (direct dep), tables found by a `Journal Club` header cell (PGY from a title row or the paragraph above). Word splits runs mid-token, so cells are joined per paragraph and dates parsed with ALL whitespace stripped; a self-closing `<w:p/>` must not match the paragraph regex (it once swallowed later tables). Names use `matchLectureRosterName` (injected), plus a space-stripped fallback only when it finds nothing. Writes: `ayData[AY].jcDates` via the single seam `writeJcDatesToAy` (D1 will redirect), `jcPresentDates` + `grLectureDates` (lecture AND M&M) MERGE only. File contents never stored.
- **Provenance** (`importLog.js`): every importer's log entry carries `populated[]`, `hash`, `by` (stamped in the root `setImportLog` wrapper), and `blockStarts`/`ays` scope; the Dashboard "Sources" panel reads it via `sourcesFor`. New importers must log the same fields (metadata/counts only).
