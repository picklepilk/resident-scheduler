### Shift catalog & data model
- `shiftActiveOnDow`: a `SHIFT_DOW`-absent shift always exists; a `SHIFT_DOW`-present one only on its listed days — six call sites in the big file plus `scheduleQuality.js`'s coverage-miss scan.
- Coverage: generator fills to min (hard), tops up toward max only for under-target residents (soft cap). `PED-S` weekday existence is `SHIFT_DOW`, a separate mechanism.
- `BLOCK_TARGETS.EM_HOME_2__EM_EMS/EM_TOX = 7` (flat 19 unreachable under the 2-weekday gate; `blockTargetReachability.test.js` asserts generically). These rotations get a strong soft non-PED penalty (`emEmsToxNonPedsPenalty`), NOT a hard PEDS-only strip (measured to cost real coverage).
- Chief's call-in/payback convention: per-resident shift counts read off real historical schedules must never derive/validate targets; small over/under is expected noise.
- Vacation (`vacationDates`) vs approved-off (`approvedDatesOff`): behave identically (hard off) but stay distinct fields (VAC teal vs OFF orange markers). `offRequestNotes` (reason/note stamped at approval time by `RequestsTab.decide()`) rides `res_em_roster`; `offReasonText` is the single reader, 200-char cap.
- Off-service residents live in `block.offServiceResidents[]` with `availabilityMode: 'full'|'ranges'|'days'` (checked by `isAvailableOnDate`). Resident-level fields inside block/roster objects need no new backup key.
- `blocksHistory` published-only consumers: JC cap counting, AY carryover. `computeBuyDownsApplied` deliberately counts unpublished too (and skips the live block's own snapshot).
- BAMC residents with no `blockType` default to `'EM'` rotation in `isSchedulable` (read-time fix; Off-Service tab never assigns one).
- Chief roles: global `resident.chiefRole` (`academic`/`admin`/`scheduling`), any → 16-shift target; only `academic` bars Tue eve/night (checked on `chiefRole` directly, NOT the legacy `effectiveChiefRole` fallback). `effectiveChiefRole` is read-time-only compat for old `isChief`.

### Scheduling rules (full originals)
- **Circadian** (`NIGHT_RULES` 4-6-6): eve→day next day (and reverse) hard errors; max 6 nights/block (`isNightOnlyResident` FM-3 exempt); ≥24h post-night rest before day/eve OR Grand Rounds is soft `rule:'postNightRest'`, checked BOTH directions. Hard circadian + GR-gap checks run in `validateAll` regardless of `appSettings.enforceRest` (that toggle gates only the pairwise rest-hours check). Rolling 80h/wk pro-rated cap → generator reason `'hoursCapped'`. (superseded 2026-09-27: day→eve allowed)
- **Trauma**: TRAUMA-D/N hard-clamped max 1 in generator regardless of editor. Hard ≤2 TRAUMA-N per contiguous night run (`traumaRunCapped`; `validateAll` error; solver rule 43, never relaxed). Soft: `traumaSecondInRun`/`traumaMidRun`/`nightDurationAlternation` (alternation exempt at 12h-window boundaries via `alternationExemptDates`).
- **Night-run shape**: scoring stopped penalizing runs 2–6 (only isolated singles cost); `validateAll`'s advisory "isolated night stint" warning still fires below `minRun` 5 — deliberately divergent, don't conflate. Soft `secondRestDay` prefers 2nd day off after 3+ night runs.
- **Max 6 consecutive work days** (`MAX_CONSECUTIVE_WORK_DAYS`, strict ACGME): a day counts if a shift is assigned (current block OR prior block's tail via `prevBlockTailSchedules`), OR it's the resident's GR weekday (`grWorkDow`: EM_HOME Wed, EM_BAMC Thu), OR a JC presenting date — UNLESS the date is vacation/approved-off. Boolean per date (working GR day = one day). Shared by validator, generator, picker (`prevTail` threaded from `ScheduleGrid`). A run with zero actual shifts (`runHasShift` false) raises no error.
- **Journal Club** (`src/lib/journalClub.js`): 18:00–21:00; "worked" derived from `SHIFT_TIMING` overlap (`shiftOverlapsJC`), never a hand list. Max 3/AY counted across Published blocks + live. JC dates chief-editable per AY (`ayData[AY].jcDates`): absent = derive first Tuesdays; explicit `[]` honored. Consumers use `resolveJcDates`/`jcDatesInRange`/`isJcDate`/`isJcDateAnyAy` — never re-derive. `ayWindowFor().end` is EXCLUSIVE; blank block AY falls back to `getAcademicYearFor(startDate)`; `validateAll` scopes `jcPresentDates` to the AY window. Generator hoists a JC-date Set per run. Presenter's overlapping shifts hard-stripped that day.
- **Holidays** (`src/lib/holidays.js`, `ayData[AY].holidays`): named multi-day entries. **Absent config derives NOTHING** (deliberate opposite of jcDates); `defaultUsHolidays` only behind "Add US defaults" (merges by start date). "Worked" = shift STARTS on the holiday date. Time off on a holiday = unavailable, not spared (count 0 steers next holiday toward them). `holidaySpread` coeff 8 in the existing last vector slot; `holidayEquity` tiny fill-time preference; `holidayYearly` maintained at the same 3 counter sites as `traumaNightYearly` (exact inverse pair with repair's revert). Card renders nothing when unconfigured; no-config generation is bit-for-bit unchanged (tested).
- **GR lecture dates** (`grLectureDates`): no eve/night the day before — hard-stripped + validated; dates validated against `grWorkDow`. M&M dates merge into this same field.
- **Seniority**: FLEX soft (`{primary:2,fallback:3}`, junior beats unfilled, `report.seniorGaps`). **POD hard** — staffed POD without PGY-3 is a `validateAll` ERROR unless it's the resident's own 3rd Wellness Wednesday (`podWellnessSubstituteAllowed`); generator's POD branch enforces it too (`'pgy3Required'` unfilled reason). **Wednesday DAY shifts exempt from both** (`seniorCompositionExempt` — GR makes EM seniors structurally absent; off-service/APPs cover). That helper has FOUR call sites that must stay in lockstep: `validateAll` senior loop, `fillDayPass` POD branch, `fillDayPass` FLEX branch, `narrowForSeniority`/`podStillSatisfied`.
- **EM-count composition (soft, both engines)**: POD@2 wants 2 EM, POD@3 wants ≥2, FLEX ≥1 (`podEmComposition`/`flexEmComposition` score terms + `validateAll` warnings). `narrowForPgyGate` pool-restricts POD PGY-2 (FLEX PGY-3) while the primary PGY can cover, falls back with `report.pgyFallbacks`; EM_HOME only, never EM_BAMC; validator uses a deliberately conservative proxy (warns only when a primary is already covering).
- **Wellness Wednesdays**: block-relative Nth Wednesday per PGY (computed day rules) — `ctx.blockStart` must reach EVERY `getEligibleShifts` call site (a grid caller once omitted `ctx` and silently no-op'd this).
- **Jeopardy never collides with a clinical shift** (hard under `'warn'` AND `'block'` policy; `'off'` fully silent): `candidatePool` excludes (`'jeopardyConflict'`), `fillJeopardy` excludes already-scheduled (`'allScheduled'` vs `'allUnavailable'`), `validateAll`/`cellViolations` escalate to error. `SCORE_WEIGHTS.jeopardy` was removed as unreachable. **Off-service residents have no jeopardy**: `isJeopardyDate` gates on category `EM_HOME`/`EM_BAMC` (read-time ignore, not migration); jeopardy editors removed from off-service surfaces. Deferred (documented, unmodeled): chief runs ADMIN/METRO/ELECTIVE as multi-day jeopardy streaks + token end-of-block shift.
- **Trauma/Peds split** (`TRAUMA_PEDS_SPLIT` {trauma:8, peds:11}): two protected sub-targets via per-resident sub-caps in `candidatePool`, not one 19. `allowSplitPedsNights` lets the peds half take PED-N (9h only, never PED-N12); trauma half stays Trauma-Day-only unconditionally. **Default flipped to true** (`?? true` at all three read sites — old backups with no key now get ON). `pedsInternNightDeficit` targets 5 PED-N per split intern in both engines.
- **PED-N split (2026-08-18)**: `PED-N` 19:00–04:00, all 7 nights, owners EM_HOME_1/2/3, EM_BAMC_1, FM_1, PEDS_2/3 (Round 2b removed the old Thu–Sun gate). `PED-N-FM` 23:00–08:00, FM_3 only, Mon/Tue/Wed. Both `{min:0,max:1}`, both `type:'night'`. `PED_GUARD_LEGITIMATE_OWNER` is DERIVED from `BASE_ELIGIBILITY` for PED-N/PED-N-FM/PED-S — grant eligibility there, never hand-edit the guard. Consequences that are live: `shiftOverlapsJC('PED-N')` is now true (PED-N on a JC Tuesday counts as worked JC); night→eve-next-day is covered by the widened `postNightRest`; legacy FM `PED-N` cells were renamed via `migratePedNightAssignments` (dbReady-gated) + `LEGACY_SHIFT_ID_RENAMES` in `eligibilityOverrides.js`. PED-S similarly now all 7 days, multi-owner.
- **EM/EMS ↔ EM/TOX weekday windows swap on 2026-08-01**: both variants live in `DEFAULT_DAY_RULES.EM_HOME_2.shiftGates` distinguished by `activeWhen` (evaluated against block startDate by `gateActiveForBlock`) — don't "clean up" into one gate. EM_TOX gets soft +8 for PED-E.
- **Soft Rule Priority** (`appSettings.rulePriority`): chief-orderable `coverageMin`/`seniorComposition`/`postNightRest`. Default ranks coverage first (rest/senior compromises recorded); reordering protects the rule instead (`'restProtected'`/`'seniorProtected'` unfilled reasons). Rides `res_app_settings`, `normalizeRulePriority` handles old backups.
- Peds Wednesdays: PEDS_1/PEDS_3 `fullBlockDays:[3]`. Advocacy-days feature REMOVED — stale `specialDays.advocacyDays` in old snapshots is never read; don't migrate, don't resurrect.
- IM_2: Tue only-day, Wed only-night.

### Generator (full originals)
- `generateSchedule()`: coverage-driven, three passes via `fillDayPass` — `'min'` for everything except TRAUMA-D, then TRAUMA-D alone (PGY-1 trauma-day is deliberately the final min step — don't collapse), then `'optional'` top-up (empty pool silently skipped, max is a cap). Candidate pool recomputed fresh per slot — a cached pool once caused double-booking; the decision path must never go through a cache. Never overwrites non-empty cells (`keptCells` — covers manual entries and partial-regenerate identically).
- **Fresh MRV**: greedy re-pick of most-constrained remaining slot after every placement. Counts maintained incrementally (exact ONLY because every `candidatePool` filter reads per-resident state — a new cross-resident filter silently degrades the ordering); the cache is a SORT KEY ONLY; the count is composition-aware (effective sub-pool for FLEX/POD seniority) — that's where the measured win is, don't drop to raw pool size. Ties resolve to earliest original slot (determinism preserved).
- `generateScheduleBest()`: 20 seeded attempts (`baseSeed + i*0x9E3779B9`, `mulberry32` rng injected into `score()`'s tie-break), picked by `betterQuality` — **lexicographic** `(validateAll errors, export-blocking warnings, quality vector)`, never a weighted scalar. Any result replayable: `generateSchedule({...args, rng: mulberry32(report.seed)})`. Solver `FEASIBLE` results are NOT replayable — the returned schedule is the record.
- **Repair pass** (`repair:true`, run once on the winning seed, kept only on strict improvement): Phase 1 same-day/cross-day swaps for unfilled mins, Phase 2 rest-compromise swaps, Phase 3 senior swaps, Phase 4 bounded depth-2 ejection chains. Every move transactional (candidatePool re-check, coverage-min floor, exact revert) and narrowed by `narrowForSeniority`/`podStillSatisfied` (without them repair manufactured hard errors). Pool budget 300 (P1–3) + 200 (P4) — deliberately not shared (P1 exhausts any shared budget). Post-repair report arrays rebuilt from the final schedule, scoped to generated cells only; the quality scorer reads the WHOLE schedule including kept cells.
- **`SCORE_WEIGHTS`/`SCORE_TIERS`** (exported; `scoreWeights.test.js`): every weight classified STRUCTURAL or PREFERENCE; test is a RATCHET (bands can't grow past ceilings, every weight must be classified). Known-inert inversion: preference bands can exceed a shift's deficit worth, but `candidatePool`'s `allAtTarget` filter enforces target fairness upstream — if that filter is ever loosened, revisit (documented A/B rejected a rescale).
- Work-shape scoring: fragmentation charged only beyond `ceil(worked/6)` runs (6-day cap REQUIRES ≥3 runs at target 18); joins the existing last vector slot at 0.5 — never a 5th slot.
- **Area spread** (`SCORE_WEIGHTS.areaShare` 15 STRUCTURAL, DAY/EVE ONLY + `areaSpread` metric): `mixShare` only buckets day/eve/night, so POD-E/MT-E/FLEX-E are one indistinguishable "eve" and area concentration went unscored (measured: residents eligible for all 5 areas finishing an 18-shift block 100% in one area). `areaCount` is maintained at the SAME four sites as `nightAreaCount` (seed, `fillDayPass` commit, repair assign/unassign). **Nights are exempt** — they already have `nightAreaDiversity`, pinned at weight 2 so area spread can never compete with `nightCluster`(40); including nights tripped `chiefBenchmark`'s isolated-single-night-run guard (25 vs 23 ceiling). Weight 15 (not the concentration-optimal 25) because 25 still fails that guard at 24. **The `areaContinuity > 0` gate is load-bearing** — ungated, the term opposes `workShapePenalty`'s within-run area-churn charge and regresses it, the way the reverted Phase 2.3 type-churn term did; gated, it speaks only when a NEW run starts, so continuity governs WITHIN a run and areaShare ACROSS runs. `areaSpread` (excess over `AREA_CONCENTRATION_FLOOR` 0.5) joins the existing last vector slot at 2 — never a 5th slot. A finer per-shift-id twin was built and A/B rejected (inert on 2 of 3 fixtures; the fill-time half regressed restCompromises).
- **AY carryover** (`computeAyPriorTotals`): spreads blended with prior AY totals from PUBLISHED snapshots only, capped at 6 blocks. Strict no-op on empty history; a resident with no history is EXCLUDED from the AY population, never zeroed (zero = maximally under-worked = hammers the newest resident).
- Override capture: hand-edits to a generated schedule logged into `block.overrideLog` via `updateBlockTracked` ONLY (the single mutation choke point). Two guards: previous schedule must have a `generationReport`, and a generation itself (report identity change) is skipped. Cap 500. Report-only — nothing reads it back into generation.
- Readiness gate (`checkGenerateReadiness`): warns (with Generate Anyway) on empty relevant special-day lists + JC presenter gaps (`jcPresentersFor` shared with the planner card).
- **Under-target issues carry `rule: 'underTarget'`** — classify by that id everywhere, never by `message.startsWith('Under target')` (the message text gets suffixes appended — see conference tolerance below — and a prefix classifier is one text edit from silently breaking). `GenerationReportCard`'s per-resident line also reports WHY, via a diagnostic computed at the tail of `generateSchedule` (right after the repair pass): for every under-target resident it counts `openSlots` (dates+shifts where headroom existed and the resident was rotation-eligible) and a `blockedBy` histogram of the hard rule (`allRestBlocked`, `streakBlocked`, `nightCapped`, `halfTargetMet`, …) that rejected them from each one — reusing `candidatePool`'s own reason vocabulary via a separate `UNDER_TARGET_BLOCK_LABELS` display map (unlabelled reasons fall through to the raw id, never blank). This is diagnosis only — nothing reads it back into generation — and it's cheap: it runs after the schedule is frozen so `candidatePool`'s per-resident caches are warm. `generateScheduleBest` passes `deferUnderTargetDiagnostics:true`, which parks the scan on the report as a closure instead of running it, then invokes it once on the winning attempt and **deletes the property** — so the cost is paid on 1 of the 21 internal `generateSchedule` calls, not all 21. The delete is load-bearing: the report is persisted onto the block, a function property would vanish in the JSON round-trip, and a report still carrying one has un-filled `openSlots`/`blockedBy`. Standalone callers omit the flag and get the numbers computed inline.
- **Conference under-target tolerance**: a resident finishing exactly 1 shift short on a block that overlaps an ACEP/AAEM/SAEM window (`getConferencesInBlock`) downgrades that one `underTarget` issue from `error` to `warn` (stops blocking export) and stamps `conferenceTolerated: true` — the TARGET itself is untouched, only export severity relaxes, because inside a 12-hour 'replace' window POD/MT/FLEX 9h shifts become 12h ones that still credit +1 toward target but burn 12h of the 80h rolling cap instead of 9h, so `hoursCapped` binds sooner for everyone working that week. `conferenceTolerated` issues are deliberately absent from `EXPORT_BLOCKING_RULE_IDS` (so the export gate truly stops blocking) but ARE folded into `scoreGenerationResult`'s `blockingWarnCount` (so `betterQuality`'s lexicographic slot 1 still strictly prefers an attempt that reaches full target over one that settles for 1-short) — two callers reading the same issue list for two different questions, same idiom as `twelveHourAllows`'s per-caller `undefined` handling. Don't let a downgrade-to-warn also fall out of the scoring count, or the generator loses all incentive to hit target on conference blocks.
- Progress overlay: `startGenProgress`/`stopGenProgress` in a `finally`; `yieldToPaint()` (double rAF) awaited before every synchronous generator call so the stage label paints. z-100.

### UI conventions (full originals)
- **Dark mode**: override stylesheet in `index.css` (`.dark` sheet), NOT Tailwind `dark:` variants (thousands of class strings). Wrapped in `@media screen` so print/PDF stays light. Exempt on purpose: solid `-500/600/700` button backgrounds with `text-white`, vivid rings/outlines, modal scrims, `SidebarNav`/`DAY_MARKERS.dark` (sidebar is solid dark-navy in every theme). Auth/requests surfaces render inside AppGate's `.dark` wrapper and need the same treatment.
- **`DAY_MARKERS`**: single style table for GR/JC/WW/OFF/VAC/J + pending-R badge across all seven render sites. `onShift` variant is solid `bg-white` + colored ring + `-700` text — **never an alpha tint** (chip background bleeds through). New/changed marker = edit this table, never inline classes.
- **Schedule grid**: sticky header/footer/name-column only work because the scroll container is `overflow-auto` with a bounded `maxHeight` — don't remove the height bound. Z-ladder: cells 10 → header/footer 20 → corner cells 30 (INLINE `zIndex` — `.grid-sticky` is unlayered CSS and beats `@layer utilities` classes) → app header 50 → fullscreen 60 → progress overlay 100 → toast 200. Fullscreen is an in-app `fixed inset-0` overlay, not `requestFullscreen()`.
- **Grid readability**: zoom 50–150% applied as CSS `zoom`, **never `transform: scale`** (breaks every sticky axis); the `maxHeight` calc divides the zoom back out. All three input paths (buttons/wheel/pinch) share ONE clamp inside `setGridZoom`. Column width: `CELL_W = CELL_W_BASE + gridColExtra` local to `ScheduleGrid`. Both persist in `res_ui_prefs` (`normalizeUiPrefs`; `clampGridZoom` typeof-checks, no `Number()` coercion — `Number(true)` is 1). Two-tier header: week band height set on the band ROW (border-box), second tier sticks at `top: WEEK_BAND_H`; bands are MONDAY-started (blocks start Monday; Sunday-start splits the weekend). Weekend cells `bg-slate-100`; `border-l-2` marks Mondays.
- **Cell locking**: `block.lockedCells` inside the block (rides existing persistence); undo pairs `{schedule, lockedCells}`; generator knows nothing about locks (`runPartialRegenerate` clears only unlocked, `keptCells` protects the rest); every bulk lock action = ONE functional `updateBlockTracked` (looping per-cell floods undo); chip `draggable` disabled while lock-paint is on.
- `computeCoverageByDate` is shared by grid footer, Dashboard tiles, Calendar view — never fork it; it reads only `r.id` (works on stub snapshot rosters). `cellViolations` shared by picker + drag-drop (both sides validated against `scheduleClearing`-adjusted state; violations open `DragConfirmModal`). Root `issues`/`issueCounts` memo = ONE `validateAll` pass for all consumers.
- Dashboard is the landing tab (Home tab GONE — read old "Home tab" references as Dashboard). Hosts `BlockCalendarSection` (AY timeline of snapshots + coverage heatmaps), Current Block editor, `AYConferenceEditor`, JC/Holiday date editors, `JournalClubPlanner` (writes `jcPresentDates` via functional `setEmRoster` by id), Special Days, stat cards, `JeopardySickCallsCard`.
- **What's New**: `CHANGELOG` newest-first; change `id` only for interruption-worthy releases; `res_whats_new_seen` device-local; `markChangelogSeen()` is the single writer; `WhatsNewTab` freezes its unseen set at mount so New pills survive the visit that clears them; `renderChangelogText` shared (bold-only markup, deliberate).
- `TimeOffModal` paint math is pure in `src/lib/dateSetPaint.js`; deliberately NOT wired into `ResidentForm` (nested-modal unverified). Requests tab is the only tab component outside the big file; it re-checks its own session/role.
- Coverage tab math lives in `src/lib/coverageComposition.js`; reproduces `computeCoverageByDate`'s two guards (skip `SHIFT_DOW`-inactive, resolve `twelveHourStateFor` once per date).
- **Schedule-tab row grouping** (Category/PGY/Rotation, second `SubTabs` above the category filter pills): pure partition logic in `lib/scheduleGrouping.js`'s `groupResidents(residents, mode, {categories, blockTypes, isEm})` — lib-legal only because `CATEGORIES`/`BLOCK_TYPES_EM`/`isEmResident` are passed as PARAMETERS, never imported (lib/* may never import `ResidentScheduler.jsx`). Always returns `[{cat, members}]`, same shape the category-only version always returned — `cat` is a synthesized `{id,label,badge,rowBg}` descriptor in PGY/rotation mode, which is why `ScheduleGrid`'s banner render and `ResidentCardsView` needed no edits to gain the other two modes. Runs on `visibleResidents` (after the category pills + hide-unscheduled), so filtering and grouping compose. `PGY_OTHER`/`ROT_OTHER` catch-all buckets exist so a garbage `pgy` or an EM resident with an unrecognized `blockType` still renders a row instead of vanishing — same posture as the hide-unscheduled toggle.
