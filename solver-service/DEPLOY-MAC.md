# Hosting the solver on a Mac Studio (pool member "Mac")

Written 2026-11-21. Adapted from the EM Scheduler Mac host. The Mac sits on another tailnet and is
never exposed itself: picklehub tunnels to it over ssh and publishes it on its own Funnel under the
path `/rs-mac`. Windows PCs: `DEPLOY-WINDOWS.md`. Pi: `DEPLOY-PI.md`.

## Layout
- Mac: LaunchAgent `com.residentscheduler.solver` (`RunAtLoad`, `KeepAlive`), binds **127.0.0.1:8766** only.
- Code `~/resident-solver/solver-service`, venv `~/resident-solver/.venv`, config `~/resident-solver/solver.env` (chmod 600, never committed; template `deploy/mac/solver.env.example`), log `~/resident-solver/solver.log`, run telemetry `~/resident-solver/runlog/runs.jsonl`.
- `start.sh` (generated by `install.sh`) refuses to start unless `SOLVER_AUTH_MODE=supabase`, `SOLVER_ALLOWED_EMAILS` and `SUPABASE_URL` are set and not placeholders (`YOUR-PROJECT`, `@example.org`). `SOLVER_HOST_KIND=pc` makes `/health` report a PC host: app uses `/jobs` + poll and the advertised budget.
- Sleep: uvicorn runs under `caffeinate -i` (no idle sleep while the service lives). Resident's API has no pre/post-job hook mechanism (EM's `caffeinate` hooks are an EM-only feature), so wrapping the process is the simplest correct option; the Mac Studio is a desktop, so permanent idle-sleep prevention is fine.
- picklehub: user unit `deploy/pi/rs-solver-mac-relay.service` runs `ssh -N -L 127.0.0.1:8769:127.0.0.1:8766` to the Mac with key `~/.ssh/rs_mac_relay`, `Restart=always`.

## Steps
1. Mac: enable Remote Login (ssh). Get its login name and tailnet IP.
2. picklehub: `ssh-keygen -t ed25519 -N "" -f ~/.ssh/rs_mac_relay`. Add to the Mac's `~/.ssh/authorized_keys` (one line):
   `restrict,port-forwarding,permitopen="127.0.0.1:8766",command="/usr/bin/false" <contents of rs_mac_relay.pub>`
   Accept the Mac host key once (`ssh -i ~/.ssh/rs_mac_relay USER@MAC_IP` fails with the forced command, but the known_hosts entry is saved).
3. From a machine that can ssh to the Mac (repo root): `sh solver-service/deploy/mac/push.sh USER@MAC_IP`. First run creates `~/resident-solver/solver.env` and stops: edit it (Supabase URL, allowlist; same values as the Pi), then re-run the same command. Expect `/health` JSON at the end.
4. picklehub: copy `deploy/pi/rs-solver-mac-relay.service` to `~/.config/systemd/user/`, replace `USER@MAC_IP`, then `systemctl --user daemon-reload && systemctl --user enable --now rs-solver-mac-relay`.
5. picklehub funnel path: `sudo tailscale funnel --bg --https=10000 --set-path /rs-mac http://127.0.0.1:8769`. Port 10000 is already the Pi solver at `/`; `--set-path` adds a mount without disturbing it. Check `tailscale funnel status`.
6. Verify: `curl https://picklehub.tail424ec7.ts.net:10000/rs-mac/health`.
7. Netlify env `VITE_SOLVER_POOL`: add `Mac=https://picklehub.tail424ec7.ts.net:10000/rs-mac` **first** (Auto picks the first usable member), keep the existing entries after it, redeploy.

## CSP
`netlify.toml` `connect-src` is origin-based and already lists `https://picklehub.tail424ec7.ts.net:10000`. CSP source expressions without a path match the whole origin, so the `/rs-mac` path needs no change. `parseSolverPool` accepts URLs with a path (only trailing `/` is trimmed), and the client appends `/health`, `/solve`, `/jobs`, `/jobs/{id}` to the base.

## Why no root-path shim
`tailscale funnel --set-path /rs-mac` strips the mount path before proxying (EM's `prefix.py` documents this; its `EM_SOLVER_ROOT_PATH` middleware is only a defensive extra for proxies that keep the prefix). The resident API sees plain `/health`, `/solve`, `/jobs/...`, and returns relative job ids only, so nothing needs the prefix. No API change. If step 6 ever returns 404 while `curl 127.0.0.1:8769/health` on picklehub works, Tailscale kept the prefix and a shim would be needed then.

## Ops
- Mac: `launchctl print gui/$(id -u)/com.residentscheduler.solver`, `tail -f ~/resident-solver/solver.log`. Re-run `push.sh` to deploy (bootout, then bootstrap with retry for launchctl error 5).
- Summarize runs: `python -I tools/runs_summary.py ~/resident-solver/runlog/runs.jsonl`.
- picklehub: `systemctl --user status rs-solver-mac-relay`, `journalctl --user -u rs-solver-mac-relay -f`. Mac must be on and logged in (LaunchAgent is per-user); if off, the pool shows it offline and Auto falls to the next member.

## Rollback
1. Netlify: remove the `Mac=` entry from `VITE_SOLVER_POOL`, redeploy.
2. picklehub: `sudo tailscale funnel --https=10000 --set-path /rs-mac off`; `systemctl --user disable --now rs-solver-mac-relay`.
3. Mac: `launchctl bootout gui/$(id -u)/com.residentscheduler.solver`; optionally delete `~/Library/LaunchAgents/com.residentscheduler.solver.plist` and remove the `authorized_keys` line.
