# CLAUDE.md reference detail

Verbatim detail moved out of `CLAUDE.md` to keep it short. The rules themselves stay in `CLAUDE.md`; this file holds the supporting mechanics, dates and rationale. Read the matching section before changing the area.

## Test and quality baselines
- Quality baselines: `UPDATE_QUALITY_BASELINE=1 npm test` regenerates `qualityBaseline.<variant>.json` (refuses worse numbers unless `FORCE_QUALITY_BASELINE=1` also set). 5-seed averages + tolerance; one file per variant (`generator.baseline.<variant>.test.js`, own JSON) — **don't recombine** (shared file clobbers under parallel update). Variants `standard`/`understaffed`/`vacationHeavy`/`conferenceBlock`; only `conferenceBlock` has non-empty `ayConf` (exercises 12h conference machinery). Run baseline files ONE AT A TIME when investigating timing.
- **`Timeout calling "onTaskUpdate"` = one worker ran >60s without a macrotask** (between-test awaits are microtasks; timers fire before the queued RPC reply is read) — NOT CPU contention (capping workers didn't fix it). Heavy multi-seed tests must be `async` and `await new Promise(r => setImmediate(r))` per seed (see `baselineSuite.js` `captureFor`, `generator.underTargetLift.test.js`). `vitest.config.js` sets 120s test/hook timeouts (work in `beforeAll`).
- Solver parity: `SOLVER_PARITY=1 npx vitest run src/lib/solverParity.test.js` (bash) or `$env:SOLVER_PARITY=1; npx vitest run ...` (PowerShell). No npm script — repo has no `cross-env`, and `VAR=1` scripts no-op under Windows cmd.

## Cloud sync (`// ─── SUPABASE SYNC ───`)
- Hand-rolled PostgREST `sbFetch` (15s timeout); supabase-js used only for `getAccessToken()`. `SUPABASE_ENABLED` from `%VITE_*%` token injection; `isUnresolvedToken` = unconfigured. Real doc = `res_state` row `id:'main'`, whole doc as jsonb.
- **`res_state` RLS is admin-only** (2026-10-14, `migrate_res_state_admin_only.sql` — DEPLOY ORDER: client ships before migration runs, else admins lock themselves out). `sbFetch` `Authorization` = caller's session JWT via `getAccessTokenBounded()` (5s cap); anon key only when genuinely no session (resolved, not timed out) or `AUTH_ENABLED` false — a timeout must NOT fall back to anon while `AUTH_ENABLED` (masquerades as the empty-result ambiguity `sbIsAdmin()` resolves). Confirmed data-exposure gap if anon key sent: every resident's name + full schedule readable with the public anon key. Residents read via `resident_block_lookup()` from `src/residentRequests/blockLookup.js`.
- **Versioning + audit history** (2026-10-14, `migrate_res_state_history.sql` — DEPLOY ORDER is the OPPOSITE: migration FIRST, client second; additive, while a new client's `?version=eq.N` PATCH 400s on an unmigrated DB). `version`/`updated_by`/`updated_at` set ONLY by triggers `res_state_set_audit_fields` (BEFORE INSERT OR UPDATE, overrides client) + `res_state_archive_history` (AFTER UPDATE, archives OLD into `res_state_history`). `res_state_history`: admin-select-only via `is_admin()`, no write policies (trigger only); keeps newest 200 per `row_id`.
- Save paths: `sbSaveStateVersioned` (steady state) PATCHes `?version=eq.N`; 0 rows = another admin won, `openConflict` shows `cloudConflict` modal (Reload theirs / Overwrite with mine / Download JSON). Full-replace actions (first seed, Import Backup, playground start-fresh, Version History Restore) use `sbSaveStateExplicit`: loads real current version (never trust a stale local flag), seeds via `sbSeedState` (`Prefer: resolution=ignore-duplicates`, never `merge-duplicates`) only if absent, then versioned PATCH. `null` = lost race: root-component callers `openConflict`; Import/Restore (SettingsTab) abort with "reload and try again" toast.
- `dbReady` stays false if mount-time load fails. `row == null` is AMBIGUOUS (no row vs RLS-filtered caller): mount effect checks `sbIsAdmin()` (`is_admin()` RPC) before trusting empty as safe-to-seed. `cloudBaselineRef` is `{values, version}` — destructure, not an array. Debounced 1.5s save; `flushPendingCloudSave()` awaits pending timer AND in-flight save; `saveCloudNow` no-ops while `cloudConflict` is up (checked via ref, not state — stale debounce closures).
- Settings → Version History: `sbFetchHistory` metadata only (last 50, no `data`); `sbProfileEmails` uuid→email; `sbFetchHistoryData` lazily fetches ONE row when opened — never all 50. Preview = `src/lib/stateDiff.js` `diffState` (counts only). Restore = `flushPendingCloudSave()` + `sbSaveStateExplicit` + cloud-first-then-reload; refused in demo mode.
- `clearAll()`/`importData()`: cloud op FIRST, then local + reload; both set `syncSuspended`; both early-return in demo mode.
- **Playgrounds** (2026-10-15, replaced single shared demo sandbox): per-admin `res_state` rows `pg_<ownerUid>_<rand>`; pure id/guard/diff logic + tests in `src/lib/playgrounds.js` (`npm test` can't exercise cloud paths). `physKey()` rewrites `res_` → `res_demo_`, one physical slot for the active playground; `res_demo_mode` holds its row id (legacy `'true'` = old shared demo, never auto-entered, offered once to Resume-as-new or Delete). `activeRowId` resolves it; `assertWriteTargetRowId` guards every write path. Local-only: ONE playground (`res_pg_local_meta`). Promote: cloud-only, typed-confirm, merges only matched block's `schedule`+`lockedCells` via versioned PATCH — never roster/settings/rules.
- Jeopardy ledger in `appSettings.jeopardyLog`, not its own `res_*` key: an older bundle's whole-document cloud write would silently drop a 10th key, but round-trips unknown `appSettings` sub-keys.

## Auth detail
- Admin email allowlist: promotion keys off `auth.jwt()->>'email'`, never `new.email`; membership check is zero-argument (no enumeration oracle); table has RLS on with no policies; affects first row creation only.
- Four BEFORE triggers: `enforce_cancel_only_status`, `enforce_request_identity_immutable`, `enforce_resident_id_immutable`, `enforce_profile_role_change_rules`. `migrate_block_pending_account_access.sql` is the reference pattern for folding `role <> 'pending'` into a policy (a client-only pending check once allowed impersonation via `/requests`).
- `resident_block_lookup()` returns hand-picked jsonb only: block id/name/startDate/endDate, `ayData`, roster id/firstName/lastName.

## Data model detail
- `getShiftTarget`: a delta that zeroes the target returns `null`, not `0` (`0 != null` would keep the resident in fairness spread as a maximal outlier). `computeQualityMetrics`' second `baselineTargets` map keeps its per-resident `?? target` fallback. Buy-downs are DELTAs (survive `SHIFT_TARGETS` changes); `ImportMatrixModal` MERGES assignment records (replace would wipe deltas/isChief).
- `offServiceWindowTargetDelta` wrapper collapses zero delta to `null` via `status && status.delta !== 0 ? status.delta : null` (NOT `status?.delta ?? null` — `0 ?? null` is `0`, a bogus target adjustment).
- `availableRanges` is UNCLAMPED (2026-10-14): `buildOffServiceResidentsForBlock` stores the REAL ER rotation window — clamping to the imported block silently defeated `offServiceWindowStatus` straddle math. `isAvailableOnDate` only gets in-block dates, so no leak. `OffServiceStraddleBadge` (+ pure `src/lib/offServiceWindow.js`) at all 3 `offServiceWindowStatus` call sites; detail in `imports-exports` skill.

## Scheduling rule detail
- Trauma day guard: `stripTraumaDayForNonTraumaBlock` inside `getEffectiveEligibility` (post-resolution, like the PED guard) — NOT a shiftGate, since a saved dayRules override replaces `shiftGates` wholesale and once silently dropped the default gate. Rule id `traumaDayRotationGuard` (tier `program`).
- Consecutive work days: `isStreakWorkDay` = assigned shift (incl. `prevBlockTailSchedules`). Shared by validator, generator, picker; solver's `workday_limits.py` mirrors via always-empty `obligations` payload field (kept, unused). Chief decision 2026-10-15: shift-less GR weekday/JC date no longer extends a run.
- Rest: GR hours toward 60h/72h weekly caps: 2h after eve (10:00–GR_END_H), 2h after a night ending that morning (GR_START_H–10:00), else 4h — `lib/acgmeHours.js` `grWindowFor`/`grHoursOn`.
- Computed-date rules (2026-10-18, `src/lib/ruleDates.js`): First Friday (`ayData[AY].ruleDates.firstFriday`), Wellness Wednesday (`ayData[AY].ruleDates.wellnessWednesday[pgy]`, per PGY), Journal Club (`ayData[AY].jcDates`). Calendar math is a SUGGESTER only (Dashboard AY settings Suggest buttons). `computedDayRules` in Day Rules only switch a rule on/off per category. Consumers: `isLoggedDate`/`loggedDates` (lib), `isWellnessWednesdayFor`/`wellnessWednesdayDatesFor` (big file). One-time `appSettings.ruleDatesMigrated` migration (dbReady-gated) materialized the old derived dates; pre-generate gate = `missingRuleDates` via `checkGenerateReadiness`.
- Journal Club (`src/lib/journalClub.js`): absent config = NO dates (was first Tuesdays until 2026-10-18); explicit `[]` honored. `ayWindowFor().end` EXCLUSIVE.
- Seniority exemption (`seniorCompositionExempt`, Wednesday DAY shifts) call sites: `validateAll` senior loop, `fillDayPass` POD branch, `fillDayPass` FLEX branch, `narrowForSeniority`/`podStillSatisfied`.
- Hand overrides (2026-10-18, `src/lib/handOverrides.js`, `rulePolicy.js` `isHandOverridable`): picker's "needs override" list, drag-drop, confirm + note. Record = `block.handOverrides[rid][date] = {shiftId, ruleIds, note, at, by}` written in the SAME `updateBlockTracked` (via `syncHandOverrides`, also prunes stale; undo stack carries it). Entry counts only while the cell still holds `shiftId`. `validateAll`/`cellViolations` downgrade covered errors to `warn` + `overridden:true` (program ids are not in `EXPORT_BLOCKING_RULE_IDS` - keep it so). `buildSolverPayload` THROWS (`code: 'HAND_OVERRIDES'`) for live overrides except `traumaDayRotationGuard` on non-trauma-cap subjects (pinned cell could be INFEASIBLE) -> `engineUsed: 'skipped-overrides'`, built-in result + explicit toast. Aggregate rules (`nightRunMax`, `bamcWedNight`, `traumaPedsSplit`, `jcMaxPerAy`) store `measured` at confirm; downgrade only while current <= stored.

## 12-hour window detail
- `twelveHourStateFor` returning null would make every 12h minimum live on every date (real latent bug worth 280 phantom coverage misses in fixtures). `getCoverageFor`'s 4th param is the state object; `undefined` = "no date context" → base numbers.

## Generator detail
- Replay: `report.replay.truePrimaryOnly` false → `generateSchedule({...args, rng: mulberry32(report.replay.seed), repair: report.replay.repair})` (`repair` is false when an unrepaired attempt won; replaying it with `repair: true` would mutate it); true → also replay the true-primary-only second step with `clearFirst: false` (see `generateScheduleBest` header). Solver `FEASIBLE` results NOT replayable.
- Ranking follows Soft Rule Priority: `scoreGenerationResult`'s `blockingWarnCount` = `countBlockingWarns(issues, rulePriority)`; when `rankedBelowCoverage(rulePriority, softId)` (`lib/rulePriorityRanking.js`; `restRankedBelowCoverage` = postNightRest wrapper; default order) holds, that soft rule's warnings (`postNightRest`; `seniorComposition` = `podPgy3Composition`/`flexSeniorComposition`, map `RANKED_SOFT_RULE_ISSUES`) are NOT counted there - they count only in their own priority-ordered vector slot, both fed from the same validateAll pass (`countSoftRuleIssues`; `report.seniorGaps` is dormant/always empty, don't use it), so fewer holes beats fewer rest/composition warnings. Remaining override-tier warnings with no Rules-tab entry (`nightsTotalBlock`, `approvedDayOff`, etc.) still sit in slot 1 and outrank holes. Export gate (`issueCounts.restWarns`, `EXPORT_BLOCKING_RULE_IDS`) UNCHANGED - rest and composition warnings still need ack. Solver mirrors rest in its staged objective; composition is hard there.
- Time budget + LNS (B1): `generateScheduleBest(args, {timeBudgetMs, lnsIters, lnsTimeMs})` — `timeBudgetMs` keeps drawing seeds past `attempts` (same derivation; 55% of budget when LNS on, rest goes to LNS); absent = exactly `attempts` (baselines pin `attempts:20` + `lnsIters: BASELINE_LNS_ITERS`=40, never a time cap — non-deterministic). `lnsIters` (default 0; UI passes it: Built-in `BUILTIN_ENGINE_OPTS` 20 s, solver path `POLISHED_ENGINE_OPTS` 40 iters) runs `lnsPassSteps` on the winner after repair/true-primary fix: clear a 3-5 day window of cells the generator placed (never original non-empty/locked cells), refill via `generateSchedule` (all non-empty cells kept, so normal fillDayPass/candidatePool path, state rebuilt, `repair:false`), adopt only on strict `betterQuality`. **Replay with LNS**: `report.replay.lns` = `{seed, iters}` (null = not run; `iters` = iterations actually executed): reproduce the pre-LNS schedule per the replay recipe, then `replayLns(args, preLns, report.replay.lns)`.
- Repair budgets 300 + 200 deliberately not shared.

## Solver detail
- R9 (2026-09-27): local result goes as `buildSolverPayload` `hint` (soft `AddHint`, never a hard pin like `locked[]`); solver result ships only if STRICTLY better — tie/failure keeps local, no second local run. Solver default `config.objectiveMode: 'staged'` (lexicographic, mirrors `betterQuality`); `'weighted'` kept for comparison. Tier map/gaps/tuning: `PAYLOAD_SCHEMA.md` dated R9 section.
- Modal hosting (2026-10-17, `solver-service/modal_app.py`, `solver-service/DEPLOY-MODAL.md`): `SOLVER_JOBS_BACKEND=modal` makes jobs durable via `Function.spawn`. Modal web requests cap at 150 s, so `POST /solve` there returns 400 `use_jobs` and the client uses submit-then-poll jobs when `/health` reports `jobs: durable` (`solveViaJob`; a `use_jobs` 400 gets one retry via jobs; Fly/local stay `memory` and keep `solveRemote`). `SOLVER_NUM_WORKERS` overrides the container-misreported `os.cpu_count()` when `numWorkers` is 0/absent.
